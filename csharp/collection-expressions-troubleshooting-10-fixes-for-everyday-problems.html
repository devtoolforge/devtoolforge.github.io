What Is Collection expressions?

Collection expressions, in one sentence: [1, 2, 3] literal syntax for arrays, lists, and spans. In practice that means the details are worth getting right once, because everything downstream inherits the decision. Everything below assumes the current 2026 toolchain, but the reasoning generalizes to older versions too.

The mental model is simple: one clear definition, one clear workflow, and configuration that matches reality. Most confusion around collection expressions comes from mixing those layers — mixing definitions from different eras, or configs copied from projects with different needs. Keep them separate and the rest of this guide follows naturally.

Troubleshooting Collection expressions

When things break, symptoms cluster into a handful of patterns. Match yours here and jump straight to the fix:

  • It fails intermittently under load — look for shared state and timing assumptions that only break when things overlap
  • Performance collapsed after an upgrade — bisect the upgrade by rolling back one component at a time and re-measuring
  • Errors mention a file or component you never touched — trace the first error in the log, not the last one — the real cause is almost always earlier

If none of these match, capture a full log before changing anything. For collection expressions that log almost always names the failing layer, and the fix becomes obvious instead of guessed.

A Practical Workflow

A repeatable workflow turns collection expressions from a personality trait into a team capability:

  1. Schedule a short review each quarter to prune what no longer earns its place.
  2. Write the chosen setup down in the repository so the decision survives the next refactor.
  3. Automate the step so it runs without anyone remembering the manual command.
  4. Pick the smallest meaningful change you can ship and measure — momentum matters more than scope.
  5. Add a check to CI so regressions in collection expressions fail loudly instead of silently.

This loop — audit, change, automate, verify — is deliberately generic. It fits C# at any scale and survives every tooling generation we have seen.
