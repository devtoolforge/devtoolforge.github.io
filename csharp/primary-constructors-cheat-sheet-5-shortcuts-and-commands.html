What Is Primary constructors?

Primary constructors, in one sentence: class and struct parameters declared right in the type declaration. In practice that means the details are worth getting right once, because everything downstream inherits the decision. The good news is that the fundamentals have been stable for years, so the effort you invest compounds instead of expiring with the next release.

The mental model is simple: one clear definition, one clear workflow, and configuration that matches reality. Most confusion around primary constructors comes from mixing those layers — mixing definitions from different eras, or configs copied from projects with different needs. Keep them separate and the rest of this guide follows naturally.

Troubleshooting Primary constructors

When things break, symptoms cluster into a handful of patterns. Match yours here and jump straight to the fix:

  • It fails only in CI but passes locally — compare build modes and clean versus incremental state; CI reveals stale-output bugs instantly
  • It worked yesterday and nothing was changed — check what the OS, SDK, or package manager updated overnight before blaming the code
  • Performance collapsed after an upgrade — bisect the upgrade by rolling back one component at a time and re-measuring

If none of these match, capture a full log before changing anything. For primary constructors that log almost always names the failing layer, and the fix becomes obvious instead of guessed.

Advanced Tips
