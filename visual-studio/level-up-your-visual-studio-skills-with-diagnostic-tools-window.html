Performance Considerations

Measure first. Capture baseline numbers for the scenario you care about before touching anything, because intuition about hot paths is famously wrong. For diagnostic tools window, that usually means timing the end-to-end operation, not the method you suspect, and recording memory alongside time. Remove work before making work faster. The cheapest optimization for diagnostic tools window is usually doing less: fewer allocations, fewer passes, fewer round trips. When things break, symptoms cluster into a handful of patterns. Match yours here and jump straight to the fix:

  • It fails only in CI but passes locally — compare build modes and clean versus incremental state; CI reveals stale-output bugs instantly
  • Performance collapsed after an upgrade — bisect the upgrade by rolling back one component at a time and re-measuring
  • It worked yesterday and nothing was changed — check what the OS, SDK, or package manager updated overnight before blaming the code
