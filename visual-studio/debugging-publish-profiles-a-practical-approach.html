Performance Considerations

Measure first. Capture baseline numbers for the scenario you care about before touching anything, because intuition about hot paths is famously wrong. For publish profiles, that usually means timing the end-to-end operation, not the method you suspect, and recording memory alongside time. A ten-minute baseline turns a week of speculation into an afternoon of targeted work.

Remove work before making work faster. The cheapest optimization for publish profiles is usually doing less: fewer allocations, fewer passes, fewer round trips. Profile to find work that can be skipped entirely under normal conditions. Only then reach for caching, and only with an explicit invalidation plan.

Advanced Tips

Once the fundamentals are second nature, these are the practices that separate good setups from great ones:

  • Wrap external flakiness with retries and clear timeouts so failures are visible instead of mysterious.
  • Version your conventions: what worked for a two-person team needs revision at ten, and that is normal.
  • Record decisions next to the code they affect, in the same pull request that introduces them.
