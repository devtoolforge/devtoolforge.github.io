ASP.NET Core Minimal APIs: Build Production REST APIs with Less Code

ASP.NET Core September 28, 2026

Minimal APIs arrived in ASP.NET Core 6 as a way to define HTTP endpoints in a few lines of C#, and in the .NET 10 era they have matured into a complete, production-grade alternative to controllers. For many services, the ceremony of controller classes buys nothing: what you want is a route, a handler, validation, and JSON, wired up in the smallest possible surface.

What Are Minimal APIs?

Minimal APIs let you map HTTP endpoints directly on the application builder: a verb method, a route pattern, and a handler. The framework handles parameter binding from route, query, body, and services, and serializes the return value to JSON. No controller class, no base type, no attribute routing tables.

var builder = WebApplication.CreateBuilder(args);
var app = builder.Build();

app.MapGet("/products/{id:int}", (int id, ProductDb db) =>
    db.Find(id) is Product p ? Results.Ok(p) : Results.NotFound());

app.MapPost("/products", (ProductDto dto, ProductDb db) => { ... });

app.Run();

The handler signature is the contract. Simple types bind from route and query, complex types from JSON body, and registered services inject automatically, exactly like constructor injection in controllers.

Validation Without Ceremony

.NET 10 made validation a built-in Minimal API feature: register the validation service, apply data annotations or a validation library to your DTOs, and invalid requests return a structured 400 ProblemDetails response before your handler runs. This closes the most-cited gap that pushed teams back to controllers.

builder.Services.AddValidation();

public record ProductDto(
    [Required, MinLength(2)] string Name,
    [Range(0.01, 100_000)] decimal Price);

For richer rules, combine annotations with IValidatableObject implementations or third-party validators like FluentValidation invoked via an endpoint filter. Either way, validation errors leave your endpoint code looking like the happy path only.

OpenAPI Documentation Out of the Box

ASP.NET Core 10 generates OpenAPI 3.1 documents from your Minimal API endpoints with a single line: builder.Services.AddOpenApi() plus app.MapOpenApi(). Route groups, typed results, and XML comments flow into the document, and the built-in UI lets you explore and test endpoints during development.

Because the document is generated from code, it stays truthful: add a parameter and the schema updates on rebuild. Teams no longer maintain a separate spec and hope it matches the implementation, which removes a whole class of integration bugs.

Organizing Larger APIs with Route Groups

Critics feared Minimal APIs would devolve into a thousand-line Program.cs. Route groups solve this: group endpoints by resource, apply shared filters, tags, and prefixes, and split groups across files or extension methods. The result reads like a table of contents for the API.

var products = app.MapGroup("/products")
    .WithTags("Products")
    .AddEndpointFilter<ETagFilter>();

products.MapGet("/", GetAll);
products.MapGet("/{id:int}", GetById);
products.MapPost("/", Create).RequireAuthorization("admin");

Endpoint filters replace action filters: implement IEndpointFilter, apply per endpoint or per group, and use them for cross-cutting concerns like caching headers, feature flags, or audit logging.

Auth, Errors, and Testing

Authentication plugs in through the same builder services as controllers: RequireAuthorization() on any endpoint or group, JWT bearer or cookie schemes, and policies for fine-grained rules. Error responses should follow RFC 7807 ProblemDetails, which the framework emits for validation and can be standardized with an exception-handling middleware.

Testing Minimal APIs is refreshingly direct: WebApplicationFactory boots your app in memory, and tests hit real endpoints over HttpClient. Assert status codes, JSON bodies, and headers with your favorite test framework; no mocking of controller base classes required.

When to Choose Minimal APIs vs Controllers

  • Choose Minimal APIs for microservices, BFFs, serverless functions, gRPC-adjacent JSON services, and new APIs where you control the design
  • Controllers remain fine for very large team-standardized codebases, heavy use of MVC filters already in place, or frameworks that assume MVC (some legacy libraries)
  • Performance-sensitive hot paths benefit from Minimal APIs' lower routing overhead
  • Mixed is allowed: controllers and Minimal APIs coexist in one app without conflict

The honest summary in 2026: there is no longer a technical reason to default to controllers for new services. Minimal APIs cover the feature surface with less code and better discoverability.

Conclusion

Minimal APIs have crossed from novelty to default. With built-in validation, OpenAPI 3.1, route groups, and filters in .NET 10, they deliver everything controllers did with a fraction of the ceremony. Start your next ASP.NET Core service with MapGet and friends; your future self maintaining that service will thank you.

Frequently Asked Questions

Are Minimal APIs production ready?

Yes. Since .NET 7 added filters and .NET 10 added built-in validation and OpenAPI 3.1, Minimal APIs cover the full production feature set: auth, validation, versioning, documentation, and diagnostics.

Do Minimal APIs perform better than controllers?

They have lower routing and invocation overhead, which matters for high-throughput services. The difference is modest in typical CRUD apps but real in hot paths and microservices benchmarks.

Can I use dependency injection with Minimal APIs?

Yes, automatically. Services registered in the DI container are injected into handler parameters by type, just like controller constructor injection, including scoped and transient lifetimes.

How do I document Minimal APIs?

Add builder.Services.AddOpenApi() and app.MapOpenApi(). The framework generates an OpenAPI 3.1 document from your endpoints; enrich it with WithDescription, WithSummary, results types, and XML comments.

Can Minimal APIs and controllers coexist?

Yes. A single ASP.NET Core app can map controller routes and Minimal API endpoints together, which makes incremental migration straightforward.
