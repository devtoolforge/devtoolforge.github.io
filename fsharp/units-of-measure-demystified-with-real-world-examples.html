What Is Units of measure?

Units of measure, in one sentence: compile-time numeric units (m, s, USD). In practice that means the details are worth getting right once, because everything downstream inherits the decision. Once the defaults are deliberate, the rest of the workflow tends to fall into place.

The mental model is simple: one clear definition, one clear workflow, and configuration that matches reality. Most confusion around units of measure comes from mixing those layers — mixing definitions from different eras, or configs copied from projects with different needs. Keep them separate and the rest of this guide follows naturally.

Best Practices for Units of measure

These are the practices we see on teams where this area simply never causes drama:

  • Automate the boring parts of units of measure with scripts or tasks; humans are bad at remembering commands.
  • Keep one source of truth: if the docs and the actual configuration disagree, fix the docs immediately.
  • Review units of measure changes in code review with the same seriousness as application logic.

None of these are hard individually. The discipline is doing them every time, which is why automation and CI checks carry so much of the load.
