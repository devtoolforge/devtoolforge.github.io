Performance Considerations

For azure devops agents, that usually means timing the end-to-end operation, not the method you suspect, and recording memory alongside time. Change one thing at a time. Stacked optimizations hide which change actually helped and which added complexity for nothing. Troubleshooting Azure devops agents

When things break, symptoms cluster into a handful of patterns. Match yours here and jump straight to the fix:

  • It fails intermittently under load — look for shared state and timing assumptions that only break when things overlap
  • It worked yesterday and nothing was changed — check what the OS, SDK, or package manager updated overnight before blaming the code
  • It fails only in CI but passes locally — compare build modes and clean versus incremental state; CI reveals stale-output bugs instantly

If none of these match, capture a full log before changing anything. For azure devops agents that log almost always names the failing layer, and the fix becomes obvious instead of guessed.

Advanced Tips
